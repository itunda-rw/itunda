Itunda · IDS 3.0

The current Itunda visual language.

This showcase applies product-first hierarchy, generous rhythm, precise typography and quiet surfaces inspired by modern Korean fintech systems—while keeping Itunda Indigo, our identity, semantics and platform contracts distinctly Itunda.

01 · Principles

Inspired by the discipline, not the identity.

Itunda borrows proven design-system principles—clear hierarchy, compact type steps, consistent spacing, calm surfaces and obvious actions—then applies them to its own product language.

One core message

Every product surface should make its purpose obvious before the user studies the controls.

purpose → context → action

Hierarchy first

Large type is reserved for meaningful product moments. Most UI stays compact and scannable.

display → title → body → caption

Rhythm over decoration

A 4px base and predictable 8/12/16/24/32 steps create structure without excessive containers.

4 · 8 · 12 · 16 · 24 · 32

One decision at a time

Each surface gets a clear primary action. Secondary choices stay quiet until they are needed.

primary → secondary → tertiary

Context before controls

Explain what is happening before asking for a choice. Controls should answer a known question, not create one.

context → choice → confirmation

Itunda signature

Indigo remains the brand anchor. Reference-inspired neutrals never replace the Itunda identity.

#7472F4 · #625FE6

Value before action

Show why a task matters before presenting the control. The user should understand the benefit before committing attention.

value → context → action

Explain why

When a request needs trust, give the reason close to the decision. Explanation should reduce uncertainty, not add another step.

reason → choice → recovery
02 · Foundations

Small decisions, repeated consistently.

The showcase uses the current IDS token language rather than the older standalone blue palette. Brand color is an identity role; components consume semantic roles. Layout stays intentionally quiet so hierarchy comes from content, not chrome.

Color roles

Indigo is the current Itunda brand role. Neutrals carry most of the interface; semantic colors communicate intent.

03 · Components

Real component states, not static mockups.

These examples intentionally show the updated component contract: hierarchy, state, validation, selection and accessibility behavior.

Actions have a clear order.

Primary actions carry the task forward. Secondary actions remain available without competing for attention; destructive actions are unmistakable.

Inputs explain themselves.

Labels, help, validation and recovery stay close to the value they describe.

Used to identify your Itunda account.
Enter an amount greater than zero.

State is always legible.

Checkbox, radio and switch expose state through native semantics, shape and position—not color alone.

Navigation stays lightweight.

Selected state is explicit while the content remains the focus of the screen.

Activity

Recent account activity and transaction history.

Feedback leads to recovery.

Success confirms the result. Errors explain the problem and point toward the next useful action.
